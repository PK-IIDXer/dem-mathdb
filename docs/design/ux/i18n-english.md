# 画面の日本語・英語切り替え

## 対象と境界

表示だけを切り替える。定理名・記号名・式の型名・説明・注記・公理系名・tagなど、DBから来る値はそのまま表示する。
APIのpath・query・body、チュートリアルの入力例と送信値、比較に使う型名とcodeは言語から独立する。
検証・API・DB・seed、依存パッケージを変更しない。

## 言語の選択

headerの「日本語 / English」は通常のbuttonで、キーボード操作、`aria-label`、`aria-pressed`に対応する。
`src/i18n/language.ts`が次の優先順で読み込み時に決める。

1. URLの`?lang=ja`または`?lang=en`。有効な指定は保存する。
2. `localStorage`の`dem.language.v1`。
3. `navigator.languages`の先頭。`ja`で始まれば日本語、それ以外の有効な言語は英語。
4. 情報を取得できない場合は日本語。

不正な値、storageの例外は次の候補に進む。画面遷移のURLには言語指定を追加しない。
選択時に`document.documentElement.lang`も更新する。日付と表示用の数値には選択言語のlocaleを明示する。
静的HTMLの`lang="ja"`とtitleは維持する。

## 辞書と再描画

`messages/ja.ts`を正本とし、そのkeyと関数の引数型から英語辞書の型を作る。
`messages/en.ts`は`satisfies Messages`を使う。埋め込み値のある文章は関数にする。
`translate.ts`は表示にだけ使い、要求や比較の値を作る用途では使わない。

法的文書は匿名βの`pages/betaLegalCopy.ts`と通常版の`pages/legalCopy.ts`の対訳配列にまとめる。
通常版の英語は従来の英語sectionの文をそのまま移し、表示されなかった37件の英訳は汎用辞書から削除した。
共通辞書は577 key。頁の題名など他の場所にも表示するkeyは維持する。
日本語表示では従来の対訳併記を維持し、英語表示では英語だけを表示する。

外部storeと`useSyncExternalStore`で、単体表示のページやmemo化した行も購読する。
言語の変更でページを再mountせず、編集中の入力、選択、検索条件を維持する。
コマンド名はgetterで評価し、ID・割り当て・既存keywordsは維持する。
表示用エラーは`useDisplayError`に生成関数を保持し、APIエラーのcode・数値を保持したまま再表示する。

## 数式の読み上げ

論理の核`⊥ ¬ ∨ ∧ → ↔ ∀ ∃ = ∈`と変数だけなら英語で読む。
判定は項の内部も含む全記号について行い、記号名だけで核の記号と判定しない。
一つでも基盤の記号があれば、式全体を従来の日本語で読む。読み上げ部分に`lang="ja"`を付け、
英語の案内で日本語の記号説明から生成していることを伝える。
前提込みの定理の読みも、一つの前提だけ日本語になって英語と混ざらないよう、全体を日本語にそろえる。
この表示計算は検証・登録可否には使わない。

## 法的文書

英語表示の先頭に、参考訳であり日本語が正本・不一致時に優先する旨を示す。
制定日・条項番号は従来どおり。問い合わせのSlack通知・任意の返信先の説明も翻訳対象に含む。
今回の新しい英文・用語・匿名βの法的英文は、2026-10-30に利用者が「このままでよい」と承認した。
通常版の条文には従来承認済みの英文を使い、文面・制定日・条項番号を変更しない。

## 検査

既存試験の既定言語は日本語に固定し、日本語の期待値を変更しない。
英語辞書のkey・型・日本語混入、辞書外の日本語リテラル、言語選択の優先順、英語画面、
β入口の全条件、読み上げの言語と注記を検査する。
言語ボタンの`languageJapanese`だけは英語辞書でも「日本語」とし、理由とkeyを試験に明示する。

辞書外の日本語は`literalExceptions.json`に出現単位で列挙し、個数を含め完全一致させる。
対象は従来のDB型名、検索keywords、日本語読み上げ文法だけ。ファイル全体を例外にはしない。
`pages/betaLegalCopy.ts`と`pages/legalCopy.ts`は対訳辞書として扱い、英語部分の日本語混入と条項番号の一致を別に検査する。
3ページ×2言語×β有無の12条件で、変更前の要素・文言・lang・class・titleの記録に完全一致することを検査する。
ASTの検査前に、日本語の文字もUnicode escapeもないソースだけを判別する。
直書き・Unicode escape・JSX・template・コメントを含む9条件で、従来の全AST検査とaccept/rejectが完全一致することを検査する。
Unicode escapeを見落とす変異がこの行列で失敗することも確認する。時間切れを避けるために検査対象や判定を緩めない。

チュートリアルは9操作を実画面で日英それぞれ実行し、定理登録・6 stepの追加・検証を含む要求を比較する。
書き込みは順序も一致させ、並行GETは到着順を除き、URL・query・bodyのbytesと重複件数を比較する。
問い合わせでも同じ入力を送り、method・URL・bodyのbytesを比較する。
`DEM_I18N_REPORT_DIR`が指定された試験実行では、比較した要求の全文をJSONに保存する。
公開用のUI試験データは公開のAPIで実際に6 stepの証明を検証して記録したものを使う。
カーネル検証を省略して作ったfixtureではない。
